# graphersal-server 0.3.1 (unreleased)

**EXPERIMENTAL.** Everything here (commands, files, routes, answers) may change without notice
in later versions. This is a draft: it grows with every change until the release.

**Requires Graphersal 0.9.0**, as 0.3.0: the four crates graphersal, graphersal-serve,
graphersal-session and graphersal-mcp, pinned exactly at `=0.9.0` from crates.io.

## Per-database instructions on /mcp

0.3.0 applied a database's MCP profile (its instructions, tools and saved-query tools) only on
`/db/<name>/mcp`; the multi-database `/mcp` served the server default profile for every
database, so an operator who gave agents one `/mcp` endpoint could not tell them how to use each
database. MCP hands out instructions only at `initialize` (before a database is chosen) and one
tool list per session, so `/mcp` now delivers each database's guidance as tool-result text
([On /mcp](../guide/mcp.md#on-mcp)):

- **The block "Instructions for this database"** is appended to the answer of `use_graph` and
  of the first tool call of an MCP session on a database (named with `graph`, or the selected
  one). It holds the database's own instructions (the notes of `append` mode, the whole text of
  `replace` mode), the tools available on that database for this caller (the profile's tools the
  caller's level allows) with the session's other tools named and why they are not available
  there (`your access to this database is read-only`, `not offered by the database's MCP
  profile`, ...), and the saved queries the profile offers as tools, with their descriptions and
  parameters, to run with `run_saved_query`. The server remembers per MCP session (in memory)
  which databases it showed, and shows the block again when an alias now names another
  database, the profile changed or the caller's grant changed.
- **A call runs under its database's profile** (behaviour change): a tool the database's
  profile does not offer, or the caller's level forbids, is refused on `/mcp` as on
  `/db/<name>/mcp`, and the refusal names the tools that are available there and points to the
  block. A database without a profile of its own still gets the server default.
- **`list_graphs`** marks each database or alias with a profile of its own with
  `"hasInstructions": true`.
- **Size:** the block is at most the profile's `answer_limit_chars`; a long saved-query list is
  cut first, with a note naming `list_saved_queries`.
- **Previews:** `graphersal-server mcp profile preview NAME [--read]` ends with the block ("On
  /mcp: after use_graph NAME"); `POST /api/admin/mcp/preview` answers it as `directoryBlock`
  for a `name` (also with `endpoint` `server`); the MCP tab's previews show it, and "Preview
  /mcp" of the server default takes a database and reader or writer for it.
- The warning about `saved_query_tools` in the server default now says that the block lists the
  selected saved queries on `/mcp`.
